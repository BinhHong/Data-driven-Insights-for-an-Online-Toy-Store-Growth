# KPI Framework and Metric Dictionary

The framework is designed around the project's selected business questions and separates metrics by business domain. Each KPI is documented with its business meaning, calculation logic, source, date basis, and intended analytical use.

# 1. KPI Hierarchy

## Business Outcomes

These are the main performance indicators used to summarize business performance:

- Revenue
- Orders
- Gross Profit
- Average Order Value
- Conversion Rate
- Refund Amount

## Performance Drivers

These help explain changes in the headline outcomes:

- Sessions
- Converted Sessions
- Revenue per Session
- Units Sold
- Product Revenue
- Product Gross Profit
- Product Refund Rate
- Bundle Orders
- Bundle Order Share
- Sessions per Visitor

## Analytical Dimensions

These are KPIs used to segment the measures above:

- Date
- Product
- Traffic Source
- Device Type
- New / Repeat Session
- Landing Page
- Order Type

# 2. Date Semantics

The model contains two important date roles for website sessions and orders.

## Session Date

`Website Sessions[created_at]`

This is the active relationship to the Calendar table. **Session Date** is used for acquisition and conversion analysis, including:

- Sessions
- Converted Sessions
- Conversion Rate
- Traffic-source performance
- Device performance
- Landing-page performance
- New versus repeat session analysis
- Revenue per Session

An order may occur on a different calendar date from the session that generated it. 

## Order Date

`Website Sessions[order_date]`

This relationship to Calendar is inactive. **Order Date** is used for sales performance over time, including:

- Revenue trend
- Orders trend
- Average Order Value
- Bundle-order trend
- Revenue MoM
- Orders MoM
- AOV MoM
- YTD Revenue

## Product Sale Date

`Order Items[created_at]`

The Calendar table directly filters Order Items. This date basis is used for product-level sales metrics such as: Product Revenue, Units Sold by Product, Product Gross Profit.

## Refund Date

`Order Item Refunds[created_at]`

The Calendar table directly filters the refund fact table. This date basis is used for: Refund Amount over time, Refunded Items over time, Refunded Orders over time, Refund Amount MoM.

# 3. Sales Metrics

## Orders:
- base measure
- definition: number of completed orders.
- ```DAX
Orders =
COUNTROWS ( Orders )
```

**Important:** When Calendar filters the model through Session Date relationship, this measure represents orders generated by sessions belonging to the selected session-date period. Use `Orders by Order Date` for actual transaction-date reporting.

## Order Revenue

- definition: Gross sales value of completed orders before refunds.
- base measure
- ```DAX
Order Revenue =
SUM ( Orders[price_usd] )
```

**Primary use:**

- Revenue by traffic source
- Revenue by device
- Revenue by landing page
- Revenue per session
- Session-cohort revenue analysis

**Important:** Under the active Calendar relationship, this measure follows Session Date. Use `Revenue by Order Date` for actual sales trends.

**Format:** Currency, e.g. `$#,0.00`

---

## Order Cost

**Business definition:** Total cost of goods associated with completed orders.

**Source:** `Orders[cogs_usd]`

**Grain:** Order

**Base measure:** Yes

```DAX
Order Cost =
SUM ( Orders[cogs_usd] )
```

**Format:** Currency, e.g. `$#,0.00`

---

## Order Gross Profit

**Business definition:** Gross order revenue remaining after cost of goods sold.

**Derived from:** Order Revenue and Order Cost

```DAX
Order Gross Profit =
[Order Revenue] - [Order Cost]
```

**Format:** Currency, e.g. `$#,0.00`

---

## Order Profit Margin

**Business definition:** Gross profit as a percentage of gross order revenue.

```DAX
Order Profit Margin =
DIVIDE (
    [Order Gross Profit],
    [Order Revenue]
)
```

**Format:** `0.00%`

**Interpretation:** A blank result is returned when there is no revenue in the current filter context.

---

## Orders by Order Date

**Business definition:** Number of completed orders attributed to the actual date on which the order was placed.

**Date basis:** Order Date

```DAX
Orders by Order Date =
CALCULATE (
    [Orders],
    USERELATIONSHIP (
        'Calendar'[Date],
        'Website Sessions'[order_date]
    )
)
```

**Primary use:**

- Orders over time
- AOV
- Bundle-order trends
- Time intelligence

**Format:** `#,0`

---

## Revenue by Order Date

**Business definition:** Gross order revenue attributed to the actual order date.

**Date basis:** Order Date

```DAX
Revenue by Order Date =
CALCULATE (
    [Order Revenue],
    USERELATIONSHIP (
        'Calendar'[Date],
        'Website Sessions'[order_date]
    )
)
```

**Primary use:**

- Executive revenue trend
- Revenue MoM
- YTD Revenue
- AOV over time
- Order-type revenue analysis

**Format:** Currency, e.g. `$#,0.00`

---

## Average Order Value

**Business definition:** Average gross revenue generated by each completed order.

**Formula in words:** Revenue by Order Date divided by Orders by Order Date.

```DAX
Average Order Value =
DIVIDE (
    [Revenue by Order Date],
    [Orders by Order Date]
)
```

**Date basis:** Order Date

**Format:** Currency, e.g. `$#,0.00`

---

## Bundle Orders

**Business definition:** Number of completed orders containing two or more purchased items.

**Source attribute:** `Orders[order_type]`

```DAX
Bundle Orders =
CALCULATE (
    [Orders by Order Date],
    Orders[order_type] = "Bundle"
)
```

**Format:** `#,0`

---

## Bundle Order Share

**Business definition:** Percentage of completed orders classified as bundle purchases.

```DAX
Bundle Order Share =
DIVIDE (
    [Bundle Orders],
    [Orders by Order Date]
)
```

**Format:** `0.00%`

**Primary use:** Measures how common bundle purchases are.

To assess the financial impact of bundles, use `order_type` as a dimension together with:

- Revenue by Order Date
- Average Order Value
- Order Gross Profit, where appropriate

---

# 4. Product Metrics

Product metrics are calculated from the Order Items fact table because it contains the complete product-level transaction grain.

## Units Sold by Product

**Business definition:** Number of individual product units sold.

**Source:** `Order Items`

**Grain:** Order item

```DAX
Units Sold by Product =
COUNTROWS ( 'Order Items' )
```

**Format:** `#,0`

---

## Product Revenue

**Business definition:** Gross sales revenue generated by individual products.

**Source:** `Order Items[price_usd]`

```DAX
Product Revenue =
SUM ( 'Order Items'[price_usd] )
```

**Date basis:** Product sale / order-item date

**Format:** Currency, e.g. `$#,0.00`

**Primary use:** Product-level revenue comparison.

---

## Product Cost

**Business definition:** Cost of goods sold associated with individual sold products.

```DAX
Product Cost =
SUM ( 'Order Items'[cogs_usd] )
```

**Format:** Currency, e.g. `$#,0.00`

---

## Product Gross Profit

**Business definition:** Product revenue remaining after product cost.

```DAX
Product Gross Profit =
[Product Revenue] - [Product Cost]
```

**Format:** Currency, e.g. `$#,0.00`

---

## Product Profit Margin

**Business definition:** Product gross profit as a percentage of product revenue.

```DAX
Product Profit Margin =
DIVIDE (
    [Product Gross Profit],
    [Product Revenue]
)
```

**Format:** `0.00%`

---

## Primary Products Sold

**Business definition:** Number of sold order items marked as the primary item in the order.

```DAX
Primary Products Sold =
CALCULATE (
    [Units Sold by Product],
    'Order Items'[is_primary_item] = 1
)
```

**Format:** `#,0`

**Role:** Diagnostic metric rather than a headline KPI.

---

## Cross-Sell Units Sold

**Business definition:** Number of additional, non-primary items sold within orders.

```DAX
Cross-Sell Units Sold =
CALCULATE (
    [Units Sold by Product],
    'Order Items'[is_primary_item] = 0
)
```

**Format:** `#,0`

**Role:** Diagnostic metric for basket composition and cross-sell behavior.

---

# 5. Website and Conversion Metrics

## Sessions

**Business definition:** Number of website sessions.

**Source:** `Website Sessions`

**Grain:** Session

```DAX
Sessions =
COUNTROWS ( 'Website Sessions' )
```

**Date basis:** Session Date

**Format:** `#,0`

---

## Converted Sessions

**Business definition:** Number of website sessions that generated an order.

```DAX
Converted Sessions =
DISTINCTCOUNT ( Orders[website_session_id] )
```

**Date basis:** Session Date when used with Calendar.

**Format:** `#,0`

**Important assumption:** The model validation confirmed that each ordering session is associated with no more than one order.

---

## Conversion Rate

**Business definition:** Percentage of website sessions that resulted in a completed order.

```DAX
Conversion Rate =
DIVIDE (
    [Converted Sessions],
    [Sessions]
)
```

**Date basis:** Session Date

**Format:** `0.00%`

**Primary use:**

- Conversion trend
- Traffic-source conversion
- Device conversion
- New versus repeat session conversion
- Landing-page conversion

---

## Revenue per Session

**Business definition:** Gross order revenue generated per website session.

```DAX
Revenue per Session =
DIVIDE (
    [Order Revenue],
    [Sessions]
)
```

**Date basis:** Session Date / session cohort

**Format:** Currency, e.g. `$#,0.00`

**Interpretation:** This measures the monetization efficiency of acquired website traffic.

---

# 6. Customer and Visitor Metrics

## Unique Visitors

**Business definition:** Number of distinct users represented in website sessions.

```DAX
Unique Visitors =
DISTINCTCOUNT ( 'Website Sessions'[user_id] )
```

**Date basis:** Session Date

**Format:** `#,0`

**Important:** The dataset contains user identifiers but no customer demographic dimension. Therefore, this measure represents identifiable visitors, not a fully developed customer segmentation model.

---

## Sessions per Visitor

**Business definition:** Average number of website sessions generated per unique visitor.

```DAX
Sessions per Visitor =
DIVIDE (
    [Sessions],
    [Unique Visitors]
)
```

**Format:** `0.00`

---

## New vs Repeat Analysis

New and repeat behavior is analyzed using the session-level repeat-status attribute rather than separate KPI definitions.

The following generic measures should be evaluated by the New / Repeat dimension:

- Sessions
- Converted Sessions
- Conversion Rate
- Order Revenue
- Revenue per Session

This avoids unnecessary duplication of measures.

---

# 7. Returns Metrics

## Refund Amount

**Business definition:** Total monetary value refunded to customers.

**Source:** `Order Item Refunds[refund_amount_usd]`

**Grain:** Refund event / refunded order item

```DAX
Refund Amount =
SUM ( 'Order Item Refunds'[refund_amount_usd] )
```

**Date basis:** Refund Date

**Format:** Currency, e.g. `$#,0.00`

**Primary use:** Measures revenue leakage through refunds.

---

## Refunded Items

**Business definition:** Number of distinct order items that received a refund.

```DAX
Refunded Items =
DISTINCTCOUNT (
    'Order Item Refunds'[order_item_id]
)
```

**Format:** `#,0`

---

## Refunded Orders

**Business definition:** Number of distinct orders containing at least one refunded item.

```DAX
Refunded Orders =
DISTINCTCOUNT (
    'Order Item Refunds'[order_id]
)
```

**Format:** `#,0`

---

## Product Refund Rate

**Business definition:** Refunded product units divided by product units sold.

```DAX
Product Refund Rate =
DIVIDE (
    [Refunded Items],
    [Units Sold by Product]
)
```

**Format:** `0.00%`

**Primary use:** Comparison of refund behavior across products.

### Important interpretation rule

This measure should primarily be used for overall product comparison.

Under Calendar filtering:

- the numerator is filtered by Refund Date;
- the denominator is filtered by Product Sale Date.

Therefore, a monthly value would not necessarily represent the percentage of that month's sold units that were eventually refunded. A true monthly cohort refund rate would require separate cohort logic.

---

# 8. Time Intelligence Metrics

Time-intelligence measures are created only for KPIs required by the analytical scope.

## Previous Month Revenue

```DAX
Previous Month Order Revenue =
CALCULATE (
    [Revenue by Order Date],
    DATEADD (
        'Calendar'[Date],
        -1,
        MONTH
    )
)
```

**Format:** Currency

---

## Revenue MoM %

**Business definition:** Percentage change in order-date revenue compared with the previous month.

```DAX
Revenue MoM % =
DIVIDE (
    [Revenue by Order Date] - [Previous Month Order Revenue],
    [Previous Month Order Revenue]
)
```

**Format:** `0.00%`

---

## Previous Month Orders

```DAX
Previous Month Orders =
CALCULATE (
    [Orders by Order Date],
    DATEADD (
        'Calendar'[Date],
        -1,
        MONTH
    )
)
```

**Format:** `#,0`

---

## Orders MoM %

```DAX
Orders MoM % =
DIVIDE (
    [Orders by Order Date] - [Previous Month Orders],
    [Previous Month Orders]
)
```

**Format:** `0.00%`

---

## Previous Month Sessions

```DAX
Previous Month Sessions =
CALCULATE (
    [Sessions],
    DATEADD (
        'Calendar'[Date],
        -1,
        MONTH
    )
)
```

**Format:** `#,0`

---

## Sessions MoM %

```DAX
Sessions MoM % =
DIVIDE (
    [Sessions] - [Previous Month Sessions],
    [Previous Month Sessions]
)
```

**Format:** `0.00%`

---

## Previous Month Conversion Rate

```DAX
Previous Month Conversion Rate =
CALCULATE (
    [Conversion Rate],
    DATEADD (
        'Calendar'[Date],
        -1,
        MONTH
    )
)
```

**Format:** `0.00%`

---

## Conversion Rate MoM pp

**Business definition:** Change in conversion rate compared with the previous month, expressed in percentage points rather than percentage change.

```DAX
Conversion Rate MoM pp =
(
    [Conversion Rate]
        - [Previous Month Conversion Rate]
) * 100
```

**Format:** `0.00 "pp"`

**Example:**

A conversion-rate increase from 4.0% to 4.5% is reported as:

`+0.50 pp`

---

## Previous Month AOV

```DAX
Previous Month AOV =
CALCULATE (
    [Average Order Value],
    DATEADD (
        'Calendar'[Date],
        -1,
        MONTH
    )
)
```

**Format:** Currency

---

## AOV MoM %

```DAX
AOV MoM % =
DIVIDE (
    [Average Order Value] - [Previous Month AOV],
    [Previous Month AOV]
)
```

**Format:** `0.00%`

---

## Previous Month Refund Amount

```DAX
Previous Month Refund Amount =
CALCULATE (
    [Refund Amount],
    DATEADD (
        'Calendar'[Date],
        -1,
        MONTH
    )
)
```

**Format:** Currency

---

## Refund Amount MoM %

```DAX
Refund Amount MoM % =
DIVIDE (
    [Refund Amount] - [Previous Month Refund Amount],
    [Previous Month Refund Amount]
)
```

**Format:** `0.00%`

---

## YTD Revenue

**Business definition:** Cumulative gross order revenue from the start of the year through the current date context.

```DAX
YTD Revenue =
CALCULATE (
    [Revenue by Order Date],
    DATESYTD ( 'Calendar'[Date] )
)
```

**Date basis:** Order Date

**Format:** Currency

# 11. Metric Design Principles

The following principles are applied throughout the semantic model:

1. **Measures are preferred over implicit aggregations.**
2. **Business metrics are centralized in a dedicated measure table.**
3. **Different analytical grains are kept explicit.**
   - Orders are used for order-level economics.
   - Order Items are used for product-level economics.
   - Website Sessions are used for acquisition and conversion.
   - Refunds are used for return activity.
4. **Revenue is not treated as a single universal measure.**
   - `Order Revenue` supports session-based analysis.
   - `Revenue by Order Date` supports sales trends.
   - `Product Revenue` supports product analysis.
5. **Session Date and Order Date are intentionally separated.**
6. **Conversion is defined at session grain.**
7. **Product refund rate is not interpreted as a monthly cohort metric without additional cohort logic.**
8. **Dimensions provide segmentation; duplicate segment-specific measures are avoided.**
9. **Numeric measures return numeric values or BLANK, not text fallback values.**
10. **Time-intelligence measures are created only when they support a defined business question.**

---

# 12. KPI Framework Summary

The metric framework is organized into six analytical domains:

- **Sales** — revenue, orders, profitability, AOV, and bundle behavior
- **Product** — units, product revenue, product profitability, and product mix
- **Website & Conversion** — sessions, converted sessions, conversion rate, and revenue efficiency
- **Customer & Visitor** — unique visitors and repeat engagement
- **Returns** — refund value, refunded items/orders, and product refund rate
- **Time Intelligence** — month-over-month and year-to-date performance comparisons

Together, these metrics provide the analytical foundation required to answer the project's selected business questions while maintaining clear definitions, consistent date logic, and appropriate fact-table grain.
