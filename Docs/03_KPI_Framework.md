# KPI Framework and Metric Dictionary

The framework is designed around the project's selected business questions and separates metrics by business domain. Each KPI is documented with its business meaning, calculation logic and important notes.

# 1. KPI Hierarchy

## Business Outcomes

These are the main performance indicators used to summarize business performance:

- Revenue
- Orders
- Gross Profit
- Average Order Value
- Conversion Rate
- Refund Amount

## Performance Drivers

These help explain changes in the headline outcomes:

- Sessions
- Converted Sessions
- Revenue per Session
- Units Sold
- Product Revenue
- Product Gross Profit
- Product Refund Rate
- Bundle Orders
- Bundle Order Share
- Sessions per Visitor

## Analytical Dimensions

These are KPIs used to segment the measures above:

- Date
- Product
- Traffic Source
- Device Type
- New / Repeat Session
- Landing Page
- Order Type

# 2. Date Semantics

The model contains two important date roles for website sessions and orders.

## Session Date

`Website Sessions[created_at]`

This is the active relationship to the Calendar table. **Session Date** is used for acquisition and conversion analysis, including:

- Sessions
- Converted Sessions
- Conversion Rate
- Traffic-source performance
- Device performance
- Landing-page performance
- New versus repeat session analysis
- Revenue per Session

An order may occur on a different calendar date from the session that generated it. 

## Order Date

`Website Sessions[order_date]`

This relationship to Calendar is inactive. **Order Date** is used for sales performance over time, including:

- Revenue trend
- Orders trend
- Average Order Value
- Bundle-order trend
- Revenue MoM
- Orders MoM
- AOV MoM
- YTD Revenue

## Product Sale Date

`Order Items[created_at]`

The Calendar table directly filters Order Items. This date basis is used for product-level sales metrics such as: Product Revenue, Units Sold by Product, Product Gross Profit.

## Refund Date

`Order Item Refunds[created_at]`

The Calendar table directly filters the refund fact table. This date basis is used for: Refund Amount over time, Refunded Items over time, Refunded Orders over time, Refund Amount MoM.

# 3. Sales Metrics

## Orders:
- base measure
- definition: number of completed orders

```
Orders = 
COUNTROWS(
    Orders
)
```

**Important:** When Calendar filters the model through Session Date relationship, this measure represents orders generated by sessions belonging to the selected session-date period. Use `Orders by Order Date` for actual transaction-date reporting.

## Order Revenue

- definition: Gross sales value of completed orders before refunds.
- base measure

```
Order Revenue = 
SUM ( Orders[price_usd] )
```

**Important:** Under the active Calendar relationship, this measure follows Session Date. Use `Revenue by Order Date` for actual sales trends.

## Order Cost

- definition: total cost of goods associated with completed orders.
- base measure

```
Order Cost =
SUM ( Orders[cogs_usd] )
```

## Order Gross Profit

- definition: gross order revenue remaining after cost of goods sold.
- derived measure

```
Order Gross Profit =
[Order Revenue] - [Order Cost]
```

## Order Profit Margin

- definition: gross profit as a percentage of gross order revenue.

```
Order Profit Margin =
DIVIDE (
    [Order Gross Profit],
    [Order Revenue]
)
```

**Important:** A blank result means that there is no revenue in the current filter context.

## Orders by Order Date

- definition: number of completed orders, recorded based on the actual date the order was placed.

```
Orders by Order Date =
CALCULATE (
    [Orders],
    USERELATIONSHIP (
        'Calendar'[Date],
        'Website Sessions'[order_date]
    )
)
```

## Revenue by Order Date

- definition: gross order revenue recorded on the actual order date.

```
Revenue by Order Date =
CALCULATE (
    [Order Revenue],
    USERELATIONSHIP (
        'Calendar'[Date],
        'Website Sessions'[order_date]
    )
)
```

## Average Order Value

- definition: average gross revenue generated by each completed order.

```
Average Order Value =
DIVIDE (
    [Revenue by Order Date],
    [Orders by Order Date]
)
```

## Bundle Orders

- definition: number of completed orders containing two or more purchased items.

```
Bundle Orders =
CALCULATE (
    [Orders by Order Date],
    Orders[order_type] = "Bundle"
)
```

## Bundle Order Share

- definition: percentage of completed orders classified as bundle purchases.

```
Bundle Order Share =
DIVIDE (
    [Bundle Orders],
    [Orders by Order Date]
)
```

# 4. Product Metrics

## Units Sold by Product

- definition: number of product units sold.

```
Units Sold by Product =
COUNTROWS ( 'Order Items' )
```

## Product Revenue

- definition: gross revenue generated by products.

```
Product Revenue =
SUM ( 'Order Items'[price_usd] )
```

## Product Cost

- definition: cost of goods sold associated with sold products.

```
Product Cost =
SUM ( 'Order Items'[cogs_usd] )
```

## Product Gross Profit

- definition: product revenue remaining after product cost.

```
Product Gross Profit =
[Product Revenue] - [Product Cost]
```

## Product Profit Margin

 - definition: product gross profit as a percentage of product revenue.

```
Product Profit Margin =
DIVIDE (
    [Product Gross Profit],
    [Product Revenue]
)
```

## Primary Products Sold

- definition: number of sold items marked as the primary item in the order.

```
Primary Products Sold =
CALCULATE (
    [Units Sold by Product],
    'Order Items'[is_primary_item] = 1
)
```

## Cross-Sell Units Sold

- definition: number of additional, non-primary items sold within orders.

```
Cross-Sell Units Sold =
CALCULATE (
    [Units Sold by Product],
    'Order Items'[is_primary_item] = 0
)
```

# 5. Website and Conversion Metrics

## Sessions

- definition: number of website sessions.

```
Sessions =
COUNTROWS ( 'Website Sessions' )
```

## Converted Sessions

- definition: number of website sessions that generated an order.

```
Converted Sessions =
DISTINCTCOUNT ( Orders[website_session_id] )
```

**Important:** The data validation confirmed that each ordering session is associated with no more than one order.

## Conversion Rate

- definition: percentage of website sessions that resulted in a completed order.

```
Conversion Rate =
DIVIDE (
    [Converted Sessions],
    [Sessions]
)
```

## Revenue per Session

- definition: gross order revenue generated per website session.

```
Revenue per Session =
DIVIDE (
    [Order Revenue],
    [Sessions]
)
```

# 6. Customer and Visitor Metrics

## Unique Visitors

- definition: number of distinct users represented in website sessions.

```
Unique Visitors =
DISTINCTCOUNT ( 'Website Sessions'[user_id] )
```

**Important:** The dataset contains user identifiers but no customer demographic dimension. Therefore, this measure doesn't represent a fully developed customer segmentation model.

## Sessions per Visitor

- definition: average number of website sessions generated per unique visitor.

```
Sessions per Visitor =
DIVIDE (
    [Sessions],
    [Unique Visitors]
)
```

# 7. Returns Metrics

## Refund Amount

- definition: total amount refunded to customers.

```
Refund Amount =
SUM ( 'Order Item Refunds'[refund_amount_usd] )
```

## Refunded Items

- definition: number of distinct order items that received a refund.

```
Refunded Items =
DISTINCTCOUNT (
    'Order Item Refunds'[order_item_id]
)
```

## Refunded Orders

- definition: number of distinct orders containing at least one refunded item.

```
Refunded Orders =
DISTINCTCOUNT (
    'Order Item Refunds'[order_id]
)
```

## Product Refund Rate

- definition: refunded product units divided by product units sold.

```
Product Refund Rate =
DIVIDE (
    [Refunded Items],
    [Units Sold by Product]
)
```

**Important:** This measure should primarily be used for overall product comparison. Under Calendar filtering
- the numerator is filtered by Refund Date,
- the denominator is filtered by Product Sale Date.

Therefore, a monthly value would not necessarily represent the percentage of that month's sold units that were eventually refunded. 

# 8. Time Intelligence Metrics

## Previous Month Revenue

```
Previous Month Order Revenue =
CALCULATE (
    [Revenue by Order Date],
    DATEADD (
        'Calendar'[Date],
        -1,
        MONTH
    )
)
```

## Revenue MoM %

- definition: percentage change in order-date revenue compared with the previous month.

```
Revenue MoM % =
DIVIDE (
    [Revenue by Order Date] - [Previous Month Order Revenue],
    [Previous Month Order Revenue]
)
```

## Previous Month Orders

```
Previous Month Orders =
CALCULATE (
    [Orders by Order Date],
    DATEADD (
        'Calendar'[Date],
        -1,
        MONTH
    )
)
```

## Orders MoM %

```
Orders MoM % =
DIVIDE (
    [Orders by Order Date] - [Previous Month Orders],
    [Previous Month Orders]
)
```

## Previous Month Sessions

```
Previous Month Sessions =
CALCULATE (
    [Sessions],
    DATEADD (
        'Calendar'[Date],
        -1,
        MONTH
    )
)
```

## Sessions MoM %

```
Sessions MoM % =
DIVIDE (
    [Sessions] - [Previous Month Sessions],
    [Previous Month Sessions]
)
```

## Previous Month Conversion Rate

```
Previous Month Conversion Rate =
CALCULATE (
    [Conversion Rate],
    DATEADD (
        'Calendar'[Date],
        -1,
        MONTH
    )
)
```

## Conversion Rate MoM pp

- definition: change in conversion rate compared with the previous month, expressed in percentage points rather than percentage change.

```
Conversion Rate MoM pp =
(
    [Conversion Rate]
        - [Previous Month Conversion Rate]
) * 100
```

## Previous Month AOV

```
Previous Month AOV =
CALCULATE (
    [Average Order Value],
    DATEADD (
        'Calendar'[Date],
        -1,
        MONTH
    )
)
```

## AOV MoM %

```
AOV MoM % =
DIVIDE (
    [Average Order Value] - [Previous Month AOV],
    [Previous Month AOV]
)
```

## Previous Month Refund Amount

```
Previous Month Refund Amount =
CALCULATE (
    [Refund Amount],
    DATEADD (
        'Calendar'[Date],
        -1,
        MONTH
    )
)
```

## Refund Amount MoM %

```
Refund Amount MoM % =
DIVIDE (
    [Refund Amount] - [Previous Month Refund Amount],
    [Previous Month Refund Amount]
)
```

## YTD Revenue

- definition: cumulative gross order revenue from the start of the year through the current date context.

```
YTD Revenue =
CALCULATE (
    [Revenue by Order Date],
    DATESYTD ( 'Calendar'[Date] )
)
```
